# 雀魂 画面→牌情報抽出ツール 要件メモ v7

## 目的
雀魂(PCブラウザ版・四人麻雀)のスクリーンショットから局面情報を抽出し、JSONで出力する。
mjaiはJSONから変換する別モジュールとする。用途は何切る問題・教材作成(オフライン解析)。

## v6 からの変更点
段階1で牌譜画面5枚・和了画面1枚を確認した結果を反映した。

- 和了画面の本場: ○ → △※。0本場の和了画面に本場も局も表示されていなかった
- 和了者が親か: 画面から読む項目ではなく、翻・符・点数から求める項目に変えた
- visual_flags: 青色(hover_match)とピンク色(tinted、意味は未確認)を追加した
- highlighted: ドラの光りは時間で出たり消えたりするため、ドラの判定に使わないと明記した
- replay: 他家の手牌を伏せた牌譜と、名前が置き換わった表示があることを追記した
- 入力: ゲーム画面の外側に牌柄の背景が入る場合を追記した

## 実装の段階
1. 実画面で表示仕様を確認する(結果は「段階1の確認状況」に記録する)
2. 前処理 + 画面判定 + playing のJSON
3. replay / hora / ryukyoku のJSON
4. JSON→mjai 変換器(消費先の決定後に合成ルールを確定)

## 段階1の確認状況

### 確認できたこと
- 手番表示: 卓中央の、手番の家に向いた辺に黄色い帯が出る
- 親と席の風: 卓中央の四隅に東南西北が出て、親の「東」だけ赤地になる。並びは 左=東・下=南・右=西・上=北(左が親のとき)
- リーチ: 卓中央の点数の横に紫の棒が出る
- 供託・本場: 左上のドラ表示の下に「リーチ棒 ×n」「本場棒 ×n」で出る
- 点数の合計: リーチ1回の局面で 24000 + 25000×3 + 供託1000 = 100000 となり、合計のチェックが使える
- 赤5: 通常の5萬は「伍」が黒、赤5萬は「伍」が赤
- ドラの光り: 同じ局面でも、ドラの牌が光っている画像と光っていない画像がある
- 牌にマウスを乗せると、その牌が浮き上がり、他家の手牌で同じ種類の牌が青くなる
- 牌譜画面の巡目: 「0巡目」「9巡目」のように表示される
- 牌譜画面の他家の手牌: 表で見せる表示と、伏せる表示の両方がある
- 牌譜画面の名前: 実際の名前の代わりに「雀士1」「プレイヤー」のように表示される設定がある
- 牌譜画面の操作バー(山、局、巡目、再生ボタン)は、視点の家の河と手牌の間に出て、牌を隠さない
- 和了画面: 和了者名、ツモ/ロン、手牌と和了牌、ドラ・裏ドラ表示牌、役と翻、符、合計点(「12000点」)、「確認」ボタンが出る。本場と局は出ない(0本場で確認)

### まだ確認できていないこと
- 最終打牌マーカーの見た目
- リーチ宣言牌の横倒しの見た目
- 河の暗い牌がツモ切りの表示かどうか
- 他家の手牌のピンク色の意味。リーチ者の待ち牌(4索・7索)ではない牌(2索・5索)に付いていた。牌譜を1巡ずつ進めて、色が付く時点を撮れば確かめられる
- 対局中の画面: 鳴き・和了ボタン、自分の手番の表示
- 流局画面
- ダブロン(同時の和了)の表示
- ロン和了で放銃者が表示されるか
- 1本場以上の和了画面に本場が出るか
- 副露の並び方、カンが入ったときのドラ表示

## 決定事項

### 入力・前処理
- 入力: 静止画(PNG/JPG)。ブラウザUIや余白を含んでよい
- ブラウザのウィンドウが16:9でないと、ゲーム画面の外側に牌柄の暗い背景が入る。この牌柄を卓と取り違えずに、16:9のゲーム領域を検出する
- 検出したゲーム領域を1920×1080に正規化する

### 出力の共通定義
- schema_version: スキーマのバージョンを必ず出力する
- 牌の表記: 1m〜9m, 1p〜9p, 1s〜9s, E S W N P F C、赤5は 5mr / 5pr / 5sr
- actor 番号(絶対席): 起家を0とし、反時計回り(下家方向)に1, 2, 3
  - 局数と親の位置から画面上の席に対応づける
  - turn_actor、from_actor などは全てこの番号で表す
- viewer_actor: 画面下(視点)の家の actor 番号

### 画面判定
- screen_type: playing / replay / hora / ryukyoku / unknown
  - replay は、牌譜の操作バーの有無で playing と区別する(他家の手牌が伏せてあっても replay になる)
- hand_visibility: 4家それぞれ open / hidden(playing と replay の両方で出力する)
- overlays: ボタンや演出を記録する。必要な領域を隠していなければ受理する
- unknown には reject_reason を必ず付ける:
  - occluded(必要な領域が隠れている)
  - animating(演出中)
  - score_transition(点数移動画面)
  - game_end(終局画面)
  - sanma(三人麻雀。未対応として明示的に棄却)
  - other
- hora: 完了マーカー(合計点の表示)が出ていないフレームは animating として棄却

### 画面種別ごとの抽出項目
必須=○ / 任意=△ / 対象外=− / 要実画面確認=※ / 他の項目から求める=導出

| 項目 | playing | replay | hora | ryukyoku |
|---|---|---|---|---|
| 自分(視点)の手牌 | ○ | ○ | − | △※ |
| 他家の手牌 | 枚数のみ | open:○ / hidden:枚数 | − | △※ |
| 手番・手番の状態・最終打牌者 | ○ | ○ | − | − |
| リーチ状態 | ○ | ○ | △ | − |
| 河(順序・横倒し・表示状態) | ○ | ○ | − | − |
| 副露(構造化) | ○ | ○ | ○ | △※ |
| ドラ表示牌 | ○ | ○ | ○ | − |
| 裏ドラ表示牌 | − | − | △(リーチ時) | − |
| 点数・供託・本場 | ○ | ○ | 本場:△※ / 他:△※ | − |
| 名前・席の風・親 | ○ | ○ | 和了者名:○ / 和了者が親か:導出 | △※ |
| 局・残り枚数 | ○ | ○ | − | − |
| 巡目 | null | ○ | − | − |
| 卓種別 | △ | △ | − | − |
| 和了者・ツモ/ロン・手牌・和了牌 | − | − | ○ | − |
| 放銃者 | − | − | ※ | − |
| 役・翻・符・点数 | − | − | ○ | − |
| 流局種別・テンパイ者 | − | − | − | ○※ |

### 主要フィールドの定義
- 手番:
  - turn_actor: 次に行動すべき家
    - discard_wait のとき: 打牌する家
    - between のとき: 次にツモる家(不明なら null)
    - call_wait のとき: 視点の家
  - last_discard_actor: 最後に打牌した家(最終打牌マーカーから判定。不明なら null)
  - turn_phase の値:
    - discard_wait: 打牌待ち
    - call_wait: 他家の打牌に対して、視点の家の鳴き・和了ボタンが出ている状態に限る
    - between: 打牌後から次のツモまで
    - unknown
  - 判定は卓中央の手番表示(黄色い帯)と最終打牌マーカーを主とし、手牌枚数は検算に使う
- リーチ:
  - riichi: 宣言済みかどうか(卓中央のリーチ棒の表示を主に判定)
  - riichi_tile_index: 宣言牌の河での位置
  - riichi_position_ambiguous: その家から鳴いた副露が他家にあり、かつリーチ中なら true
- 副露: 1つの副露ごとに以下を持つ
  - type: chi / pon / daiminkan / kakan / ankan
  - tiles: 構成する牌
  - called_tile: 鳴いた牌
  - from_actor: 鳴き元
  - added_tile: kakan で追加した牌
  - ankan の場合、called_tile と from_actor は null
- 名前: 画面に表示された文字列をそのまま出す。「雀士1」のように置き換わった名前も、そのまま出す
- 和了: 1画像に1和了か複数かは段階1で確認する。スキーマは配列で持ち、要素は1件以上
- 和了者が親か: 和了画面に表示されないため、翻・符・ツモ/ロン・合計点から求める。本場が分からないため、本場による加算(1本場につき300点)を許して照合する。親と子のどちらでも説明がつく場合は null とする
- 流局種別: 荒牌流局 / 流し満貫 / 九種九牌 / 四風連打 / 四家立直 / 四槓散了 / 三家和(表示は段階1で確認)

### 牌ごとの属性
- class: 37種(赤5を含む)+ 裏向き + 空
- orientation: 縦 / 横
- visual_flags: 次のフラグの集合(複数可)
  - dimmed: 暗転・ツモ切り表示
  - highlighted: 強調・ドラの光り。光りは時間で出たり消えたりするため、ドラかどうかの判定には使わない
  - raised: ホバーで浮き上がり
  - hover_match: ホバー中の牌と同じ種類の牌の青色表示
  - tinted: ピンク色の表示(意味は段階1で確認)
- 上位候補、信頼度、座標
- status: ok / low_confidence / hidden
- 分類器は visual_flags の違いに左右されないようにし、学習データに全ての状態を含める

### 認識方式
- 領域設定: 行単位の四角形(射影補正用の4点)を設定ファイルに持つ
- 牌の分割: 領域内で動的に行う
- 非公開手牌の枚数カウント: 牌分類とは別の処理で行う
- 数字・局・巡目の表示: テンプレートか小規模分類器
- 役名: 辞書照合
- 汎用OCR: プレイヤー名のみ

### 整合性チェックと要確認フラグ
- チェック内容:
  - 同じ牌は4枚以下(赤5の枚数を含む)
  - 手牌枚数と副露数の整合
  - 手番と手牌枚数の整合
  - 点数合計 + 供託 = 総点(総点は設定値)
  - 和了画面: 翻・符・ツモ/ロンと合計点が、親か子のどちらかの点数として成り立つこと
- 違反時は、関係する牌や項目を low_confidence に降格する
- needs_review は領域ごとのフラグとする: self / others / table
  - 立つ条件: その領域の必須項目に low_confidence が1つ以上ある、または整合性チェックに違反した
  - self: 視点の手牌・副露・河
  - others: 他家の手牌・副露・河
  - table: ドラ・局・本場・供託・点数・手番など
- 信頼度の閾値は開発用データで決めて固定する

### mjai(段階4)
- JSONを入力とする独立した変換器にする。画像処理には依存させない
- 消費先が決まった後に、以下を確定する:
  - 合成ルール
  - 終端(tsumo / 他家の dahai / pon・chi / 嶺上ツモ)
  - カンドラを出すタイミング
  - tsumogiri の既定値
- 合成によって決まった部分には曖昧フラグを付ける
- 合成できない場合は出力せず、理由を記録する

## 未決事項
- mjaiの消費先と方言
- 段階1で確認する実画面の表示仕様(「まだ確認できていないこと」を参照)
- 表示言語の対応範囲
- 牌分類器の具体的な実装
- 対応する牌スキン
- 最低解像度の具体値(ゲーム領域の幅が約1020pxの画像で、他家の牌がかなり小さくなることを確認済み)

## 制約
- 入力は画像のみ。ゲームや通信への介入、自動操作は行わない
- リアルタイムの対局補助用途は対象外
- 領域の座標は設定ファイルに外出しする

## 正解データ
- 出力JSONと同じスキーマで作る
- 初回はツールの出力を人(ユーザー)が修正して作る
- このリポジトリは公開なので、他のプレイヤーの名前が写った画像はコミットしない。名前を置き換えた表示で撮るか、リポジトリの外に置く

## 受け入れ条件
- 開発用と検証用のデータを分ける。検証用は開発に使わない
- 検証セットの構成(仮):
  - 正常な画面: 画面種別ごとに30枚以上
  - 棄却すべき画面: reject_reason の種類ごとに10枚以上
  - 牌: 合計2,000枚以上
- 無言の誤り: 全ての必須項目で、status=ok の誤答を0件にする(他家の牌を含む)
- 牌単位(low_confidence は不正解扱い):
  - 自分の手牌・ドラなど table の項目: 正解率99%以上(仮)
  - 他家の手牌・河・副露: 正解率95%以上(仮)
- 画像単位(以下は「無言の誤り0件」から必然的に満たされる):
  - 全ての必須項目が「正解」か、該当する領域で needs_review が立っている割合: 100%
- 要確認の頻度:
  - needs_review が self か table で立つ画像の割合: 20%以下(仮)
  - others の割合: 計測して報告のみ
- 画面種別の判定:
  - 棄却サンプルの誤受理: 0
  - 正常な画面の誤棄却率: 2%以下(仮)
- 1枚あたり数秒以内(CPUで実行)
- 低解像度の入力には警告を出す
