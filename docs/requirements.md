# 雀魂 画面→牌情報抽出ツール 要件メモ

初版(2026-11-18)。段階1で確認した牌譜画面5枚・和了画面1枚の結果を含む。

## 目的
雀魂(PCブラウザ版・四人麻雀)のスクリーンショットから局面情報を抽出し、JSONで出力する。
mjaiはJSONから変換する別モジュールとする。用途は何切る問題・教材作成(オフライン解析)。

## 実装の段階
1. 実画面で表示仕様を確認する(結果は「段階1の確認状況」に記録する)
2. 前処理 + 画面判定 + playing のJSON
3. replay / hora / ryukyoku のJSON
4. JSON→mjai 変換器(消費先の決定後に合成ルールを確定)

## 対象ルール
- 雀魂の四人麻雀・段位戦ルール([公式の段位戦ルール説明](https://mahjongsoul.com/news/46/))を前提にする。友人戦・大会戦は設定でルールが変わるため、卓種別ごとの差は対象外とする
- このルールの主な点: ダブロン・トリプルロンあり(積み棒と供託は上家取り)。途中流局は九種九牌・四家立直・四槓散了・四風連打。パオは大三元・大四喜のみ

## 段階1の確認状況
確認に使った画像は、牌譜画面の2局面(東1局0巡目、東1局9巡目)と和了画面1枚に限られる。以下の「確認できたこと」は、その範囲で観測した見た目である。

### 確認できたこと
- 手番表示: 卓中央の、手番の家に向いた辺に黄色い帯が出る(0巡目は左、9巡目は上で観測)
- 親と席の風: 卓中央の四隅に東南西北が出て、親の「東」だけ赤地になる。並びは 左=東・下=南・右=西・上=北(左が親のとき)
- リーチ: 卓中央の点数の横に紫の棒が出る
- 供託・本場: 左上のドラ表示の下に、リーチ棒と本場棒のアイコンと「×n」が出る(棒の名前は文字では出ない)
- 点数の合計: リーチ1回の局面で 24000 + 25000×3 + 供託1000 = 100000 となり、合計のチェックが使える
- 赤5: 通常の5萬は「伍」が黒、赤5萬は「伍」が赤
- ドラの光り: 同じ局面でも、ドラの牌が光っている画像と光っていない画像がある
- 牌にマウスを乗せると、その牌が浮き上がり、他家の手牌で同じ種類の牌が青くなる
- 牌譜画面の巡目: 「0巡目」「9巡目」のように表示される
- 牌譜画面の他家の手牌: 表で見せる表示と、伏せる表示の両方がある
- 牌譜画面の名前: 実際の名前の代わりに「雀士1」「プレイヤー」のように表示される設定がある
- 牌譜画面の操作バー(山、局、巡目、再生ボタン)は、視点の家の河と手牌の間に出る。観測した2局面では牌を隠していなかった
- 河の牌の向き: 9巡目のリーチ者(左の家)の河で、6索だけ他の牌と向きが違う。リーチ宣言牌の横倒しだと考えられるが、宣言の前後の画面では確かめていない
- 副露: 9巡目の右の家の手牌の先(画面の右上)に、字牌3枚と8筒3枚が、それぞれ1枚だけ向きを変えて並ぶ。他家の手牌を伏せた表示でも表向きのまま残り、右の家の手牌は7枚(13−3×2)なので、ポン2組と考えられる。鳴いた操作の画面では確かめていない
- 和了画面: 和了者名、ツモ/ロン、手牌と和了牌、ドラ・裏ドラ表示牌、役と翻、符、合計点(「12000点」)、「確認」ボタンが出る。本場と局は出ない(0本場で確認)

### まだ確認できていないこと
- 最終打牌マーカーの見た目
- 河で向きが違う牌が、リーチ宣言牌の横倒しかどうか(宣言の前後の画面で確かめる)
- 河の暗い牌がツモ切りの表示かどうか(現時点では見た目の dimmed としてだけ記録する)
- 黄色い帯が出ない場面(演出中、打牌直後など)があるか
- 他家の手牌のピンク色の意味。リーチ者の待ち牌ではない牌(2索・5索)に付いていた。待ちの4索・7索は、牌譜で表向きのリーチ者の手牌(二二三四赤五萬 一二三四赤五六筒 五六索)から計算した。牌譜を1巡ずつ進めて、色が付く時点を撮れば確かめられる
- 対局中の画面: 鳴き・和了ボタン、自分の手番の表示
- 流局画面
- ダブロン・トリプルロンのとき、1枚の和了画面に何人分が出るか
- ロン和了で放銃者が表示されるか
- 1本場以上の和了画面に本場が出るか。和了画面の合計点に本場と供託が含まれるか
- 役満の和了画面に、翻・符の代わりに何が出るか
- 暗槓・加槓・大明槓の並び方(暗槓の伏せ牌の位置、加槓の追加牌の置き方)と、カンが入ったときのドラ表示
- 鳴かれた牌が、鳴かれた家の河に残るかどうか
- リーチ宣言牌が鳴かれた後、次の打牌が横向きになるか
- 和了画面・流局画面で、三人麻雀と四人麻雀を区別できる表示があるか
- パオが成立した和了の表示
- 和了画面で、和了者の名前と卓上の席を対応づけられる表示があるか

## 決定事項

### 入力・前処理
- 入力: 静止画(PNG/JPG)。ブラウザUIや余白を含んでよい
- ブラウザのウィンドウが16:9でないと、ゲーム画面の外側に牌柄の暗い背景が入る。この牌柄を卓と取り違えずに、16:9のゲーム領域を検出する
- 和了画面では卓の中央が覆われるため、ゲーム領域の検出に卓の中央の表示を使わない
- 検出したゲーム領域を1920×1080に正規化する。正規化の前の、元画像でのゲーム領域の大きさ(幅・高さ)を出力に残す

### 出力の共通定義
- schema_version: スキーマのバージョンを必ず出力する
- 牌の表記: 1m〜9m, 1p〜9p, 1s〜9s, E S W N P F C、赤5は 5mr / 5pr / 5sr
- 席は、次の2つの値で表す
  - seat(画面上の席): self(下)/ shimocha(右)/ toimen(上)/ kamicha(左)。卓が見える画面(playing / replay)では常に読める
  - actor 番号(絶対席): 起家を0とし、反時計回り(下家方向)に1, 2, 3。局数と親の位置が両方読めるときだけ求め、読めないときは null
- turn_actor、from_actor などは actor 番号で表し、同じ家の seat も並べて出す
- viewer_actor: 画面下(視点)の家の actor 番号(読めなければ null)
- 和了画面と流局画面には局と親の位置が出ないため、actor 番号は null になる。和了者・放銃者・テンパイ者は表示名で表し、seat は画像の中で卓上の席と対応づけられるときだけ出す(対応づけられなければ null で、status は ok)

### 画面判定
- screen_type: playing / replay / hora / ryukyoku / unknown
  - 受理する画面は、それぞれの決め手が見えたときだけ受理する。決め手が無ければ unknown
    - playing / replay: 卓の中央の表示の枠(局・残り枚数の欄と、4家分の点数欄)と、視点の手牌の列。決め手は枠と列があることで、中の数字や牌が読めるかどうかは問わない。このうえで、牌譜の操作バーがあれば replay、無ければ playing(他家の手牌が伏せてあっても、操作バーがあれば replay)
    - hora: 合計点の表示と「確認」ボタン
    - ryukyoku: 段階1で確認する
  - unknown にするのは、次の2つの場合に限る
    - 画面種別の決め手が見えない
    - 必須項目(下の表の ○ と「枚数のみ」)を読む領域が、ボタンや演出で物理的に隠れている(reject_reason は occluded)
  - 領域は見えているが値を読み取れないときは、棄却せずに受理し、その項目を null・low_confidence にする
  - 操作バーが隠れている、または写っていない牌譜は、画像だけでは playing と区別できない。そのため playing として出力し、検証セットの正解も playing とする(巡目は playing と同じく null)
  - 三人麻雀の判定: playing / replay は、卓の中央の点数欄が4家分あることで四人麻雀と判定する(点数の数字が読めるかどうかは問わない)。和了画面・流局画面で三人麻雀と区別できる表示は段階1で確認し、区別できなければ「入力は四人麻雀」を入力側の前提とする
- hand_visibility: 4家それぞれ open / hidden(playing と replay の両方で出力する)
- overlays: ボタンや演出を記録する。必要な領域を隠していなければ受理する
- unknown には reject_reason を必ず付ける:
  - occluded(必要な領域が隠れている)
  - animating(演出中)
  - score_transition(点数移動画面)
  - game_end(終局画面)
  - sanma(三人麻雀。未対応として明示的に棄却)
  - other
  - 複数の理由に当てはまるときは、上の並びで先にあるものを1つだけ出す
- hora: 完了マーカー(合計点の表示)が出ていないフレームは animating として棄却

「枚数のみ」は必須。「○※」は、段階1で表示が確かめられるまでは任意として扱う。「導出」は、求められないとき null を許す

### 主要フィールドの定義
- 手番:
  - turn_actor: 次に行動すべき家
    - discard_wait のとき: 打牌する家
    - between のとき: 次にツモる家(不明なら null)
    - call_wait のとき: 視点の家
  - last_discard_actor: 最後に打牌した家(最終打牌マーカーから判定)
    - まだ誰も打牌していない(全員の河が空)ときは null で、status は ok
    - 打牌があるのにマーカーが読めないときは null で、status は low_confidence
  - turn_phase の値:
    - discard_wait: 打牌待ち。手番の家のツモ和了・リーチ・カンのボタンが出ている状態も含む
    - call_wait: 視点の家に、他家の打牌・加槓・暗槓(国士無双の槍槓)に対する鳴き・和了のボタンが出ている状態に限る
    - between: 打牌後から次のツモまで。鳴いた後の嶺上ツモ前もここに含める
    - unknown: 上のどれにも決められない
  - 判定の手順(上から順に、最初に当てはまったもの):
    1. 視点の家に、他家の打牌などへの鳴き・和了のボタンが出ている → call_wait。turn_actor は視点の家
    2. 黄色い帯が見え、その家の副露以外の手牌が 14−3m 枚 → discard_wait。turn_actor は帯の家
    3. 黄色い帯が見え、その家の副露以外の手牌が 13−3m 枚 → between。turn_actor は帯の家
    4. どれにも当てはまらない → unknown
  - 黄色い帯と最終打牌マーカーは、ふだんから別の家を指す(帯は次に行動する家、マーカーは最後に打牌した家)。マーカーは last_discard_actor にだけ使う
  - unknown のときの出力: turn_actor は、帯が見えていれば帯の家、見えなければ null。turn_phase と turn_actor の status は low_confidence にし、table の needs_review を立てる。画面は棄却しない(screen_type は playing / replay のまま)
  - 打牌の直後に黄色い帯が次の家へ移るか(between で帯がどの家を指すか)は段階1で確認する。確認するまでは、上の手順で判定する
- リーチ:
  - riichi: 宣言済みかどうか(卓中央のリーチ棒の表示を主に判定)
  - 河の位置は、画像に表示されている河の並び(先頭を0とする)で数える。鳴かれて河から消えた牌は数えない
  - sideways_index: その家の河で、横向きに表示されている牌の位置。横向きの牌が無ければ null(status は ok)、読めなければ null(status は low_confidence)
  - riichi_tile_index: 宣言に使った打牌の、表示されている河での位置。リーチしていなければ null(status は ok)
    - 宣言牌が鳴かれた後の表示(次の打牌が横向きになるか)は段階1で確認する。それまでは、sideways_index と一致しないことがあるものとして扱う
    - リーチしているのに横向きの牌が無いときは null にし、riichi_position_ambiguous を true にする
    - その家の打牌を他家が鳴いた副露があり、宣言牌が鳴かれたかどうかを画像から決められないときは null にし、riichi_position_ambiguous を true にする
- 副露: 1つの副露ごとに以下を持つ
  - type: chi / pon / daiminkan / kakan / ankan
  - tiles: 構成する牌
  - called_tile: 鳴いた牌
  - from_actor: 鳴き元
  - added_tile: kakan で追加した牌
  - ankan の場合、called_tile と from_actor は null。伏せて表示される牌も、同じ種類の4枚として tiles に入れる
    - 伏せた牌は、種類は表向きの牌から決まるが、赤かどうかは見えない。そのため、牌の class とは別に red(true / false / null)を持たせ、伏せた5の牌は class を 5m などの通常表記、red を null にする
  - kakan の場合、called_tile と from_actor は元のポンのものを使い、added_tile に追加した1枚を入れる
  - 槓子は tiles に4枚を持つが、手牌枚数の検算では1つの面子として数える
  - 河の打牌が鳴かれた場合、その牌は副露の側でだけ数える(河にも表示が残るときは、河の牌に called の印を付けて二重に数えない)
- 名前: 画面に表示された文字列をそのまま出す。「雀士1」のように置き換わった名前も、そのまま出す
- 和了: ダブロン・トリプルロンがあるため、配列で持つ(要素は1〜3件)。1枚の画面に何人分が出るかは段階1で確認する
  - 和了牌は、手牌(tiles)に含めず winning_tile にだけ入れる
- 和了者が親か: 和了画面に表示されないため、翻・符(役満のときは役満の倍数)・ツモ/ロン・合計点から求める
  - 合計点に本場と供託が含まれるかは段階1で確認する
  - 本場が画面から読めたときは、その値で照合する。読めないときだけ、本場による加算(1本場につき300点、0以上)を許して照合する
  - 照合に使った本場の値(読めた値か、許した範囲か)を出力に残す
  - 複数人のロンでは、積み棒と供託は上家の和了者だけが受け取る
  - 照合した結果、親だけで成り立てば true、子だけなら false、両方で成り立てば null(status は ok)、どちらでも成り立たなければ null(status は low_confidence)
  - 役満のときは、翻・符の代わりに役満の倍数(yakuman_multiplier)を読み、翻・符は null にする
  - パオ(大三元・大四喜の責任払い)が成立したと画面から分かる和了は照合せず、「和了者が親か」は null(status は ok)、理由に pao を残す。役が成立していても、パオの表示が無ければ通常どおり照合する
  - ダブロン・トリプルロンが別々の画面に分かれて表示される場合、どの和了者が上家かは1枚の画像から決められないことがある。その場合は本場による加算を許して照合する
- 流局種別: 荒牌流局 / 流し満貫 / 九種九牌 / 四風連打 / 四家立直 / 四槓散了(表示は段階1で確認)。三家和は段位戦ルールに無いため含めない
- テンパイ者: キーは常に出力する。荒牌流局と流し満貫では、テンパイ者の表示名の配列(全員ノーテンなら空配列)。テンパイの表示が読めなければ null(status は low_confidence)。それ以外の流局種別では null(status は ok)。流し満貫の成立者は、別の項目に表示名で出す

### 牌ごとの属性
- class: 37種(赤5を含む)+ 裏向き + 空
- orientation: 縦 / 横
- visual_flags: 次のフラグの集合(複数可)
  - dimmed: 暗く表示されている(見た目だけを記録する。ツモ切りかどうかは表示の意味を確かめるまで出力しない)
  - highlighted: 強調・ドラの光り。光りは時間で出たり消えたりするため、ドラかどうかの判定には使わない
  - raised: ホバーで浮き上がり
  - hover_match: ホバー中の牌と同じ種類の牌の青色表示
  - tinted: ピンク色の表示(意味は段階1で確認)
- 上位候補、信頼度、座標
- status: ok / low_confidence / hidden(牌の status)
- 分類器は visual_flags の違いに左右されないようにし、学習データに全ての状態を含める
- visual_flags は任意の出力とし、正解率の採点には入れない(誤りの数は計測して報告する)

### 牌以外の項目の状態
- 局・点数・名前・手番・役・流局種別など、牌以外の必須項目も、値と一緒に status(ok / low_confidence)を持つ
- 値が null になる理由を区別する: 画面に存在しない(status は ok)と、読めなかった(status は low_confidence)
- 必須項目のキーは、値が null でも必ず出力する

### 認識方式
- 領域設定: 行単位の四角形(射影補正用の4点)を設定ファイルに持つ
- 牌の分割: 領域内で動的に行う
- 非公開手牌の枚数カウント: 牌分類とは別の処理で行う
- 数字・局・巡目の表示: テンプレートか小規模分類器
- 役名: 辞書照合
- 汎用OCR: プレイヤー名のみ

### 整合性チェックと要確認フラグ
- チェック内容:
  - 同じ牌は4枚以下(赤5の枚数を含む)
  - 手牌枚数と副露数の整合: 副露(暗槓を含む)の数を m とすると、副露以外の手牌は打牌前 14−3m 枚、打牌後 13−3m 枚。カンの直後で嶺上ツモ前は 13−3m 枚
  - 手番と手牌枚数の整合
  - 数える範囲は、画面種別ごとに次のとおり。同じ物理牌を2か所で数えない
    - playing / replay: 手牌・副露・河・ドラ表示牌
    - hora: 和了者ごとの手牌・副露・和了牌(winning_tile)・ドラ表示牌・裏ドラ表示牌。和了画面の背後に見える卓は数えない。複数の和了で共通のロン牌と表示牌は1回だけ数える
  - 赤5は、各色1枚まで(段位戦ルール)
  - 点数合計 + 供託 = 総点(総点は設定値)
  - 和了画面: 翻・符・ツモ/ロンと合計点が、親か子のどちらかの点数として成り立つこと(照合の規則は「和了者が親か」の定義に従う)
- 違反時は、関係する牌や項目を low_confidence に降格する
- needs_review は領域ごとのフラグとする: self / others / table
  - 立つ条件: その領域の必須項目に low_confidence が1つ以上ある、または整合性チェックに違反した
  - self: 視点の手牌・副露・河
  - others: 他家の手牌・副露・河
  - table: ドラ・局・本場・供託・点数・手番など
  - 和了画面と流局画面の項目(和了者の手牌・副露・和了牌・役・点数、テンパイ者の手牌など)は、すべて table に入れる
- 信頼度の閾値は開発用データで決めて固定する

### mjai(段階4)
- JSONを入力とする独立した変換器にする。画像処理には依存させない
- 消費先が決まった後に、以下を確定する:
  - 合成ルール
  - 終端(tsumo / 他家の dahai / pon・chi / 嶺上ツモ)
  - カンドラを出すタイミング
  - tsumogiri の既定値
- 合成によって決まった部分には曖昧フラグを付ける
- 合成できない場合は出力せず、理由を記録する

## 未決事項
- mjaiの消費先と方言
- 段階1で確認する実画面の表示仕様(「まだ確認できていないこと」を参照)
- 表示言語の対応範囲
- 牌分類器の具体的な実装
- 対応する牌スキン
- 最低解像度の具体値(元画像でのゲーム領域の幅で決める。幅が約1020pxの画像で、他家の牌がかなり小さくなることを確認済み)
- 処理時間の上限の具体値と、計測に使うCPU

## 制約
- 入力は画像のみ。ゲームや通信への介入、自動操作は行わない
- リアルタイムの対局補助用途は対象外
- 領域の座標は設定ファイルに外出しする

## 正解データ
- 出力JSONと同じスキーマで作る
- 初回はツールの出力を人(ユーザー)が修正して作る
- このリポジトリは公開なので、他のプレイヤーの名前が写った画像はコミットしない。名前を置き換えた表示で撮るか、リポジトリの外に置く

## 受け入れ条件
- 各段階は、その段階で扱う画面種別の分だけ、以下の条件で判定する(段階2は playing と棄却画面、段階3は replay / hora / ryukyoku)
- 精度の条件は、元画像でのゲーム領域の幅が最低解像度以上の画像だけで判定する。それ未満の画像は、警告が付くことだけを確かめ、精度は計測して報告する
- 開発用と検証用のデータを分ける。検証用は開発に使わない
  - 同じ局面を撮った画像(切り取り方や解像度だけが違うもの)は、同じ側に入れる
- 検証セットの構成(仮):
  - 正常な画面: 画面種別ごとに30枚以上
  - 棄却すべき画面: reject_reason の種類ごとに10枚以上
  - 牌: 合計2,000枚以上
  - 次の状態を含む画像を、それぞれ5枚以上: チー・ポン・暗槓・加槓・大明槓、リーチ、他家の手牌を伏せた牌譜、visual_flags の各状態、最低解像度の1〜1.2倍の画像
  - 段階3では、さらに次を含む画像を集める(表示を段階1で確かめたものに限る): ロン、ダブロン・トリプルロン、役満、1本場以上、荒牌流局、途中流局
- 牌の数え方:
  - 正解と出力は、領域(各家の手牌・河・副露、ドラ表示牌など)ごとに、並び順を保った最小の編集(見落とし・余分・置き換え)で対応づける。1枚の見落としで、それ以降の牌がすべて種類違いにならないようにする
  - 見落とし(正解にあって出力に無い)、余分(出力にだけある)、種類違い、向き違い、赤5の取り違えは、すべて誤りとして数える
  - 伏せた手牌は牌ごとの正解率に入れず、枚数の一致だけを別に数える
  - 正解率は、(正しく対応づいた牌の数)÷(正解側の牌の数 + 余分の数)とする
  - 視点の家の河と副露は「自分の手牌・ドラなど」の区分に入れる
- 無言の誤り: 全ての必須項目で、status=ok の誤答を0件にする(他家の牌を含む)
  - 必須項目のキーが出力に無いことも、無言の誤りとして数える
- 牌単位(low_confidence は不正解扱い):
  - 自分の手牌・ドラなど table の項目: 正解率99%以上(仮)
  - 他家の手牌・河・副露: 正解率95%以上(仮)
- 画像単位(「無言の誤り0件」とは別に計測する):
  - 全ての必須項目が「正解」か、該当する領域で needs_review が立っている割合: 100%
- 要確認の頻度:
  - needs_review が self か table で立つ画像の割合: 20%以下(仮)。分母は、受理した正常な画面の数
  - others の割合: 計測して報告のみ
- 画面種別の判定:
  - 棄却サンプルの誤受理: 0
  - 正常な画面の誤棄却率: 2%以下(仮)
  - 受理した画面の screen_type の取り違え: 0(例: replay を playing と出したら失敗)
  - reject_reason が正解と一致する割合: 計測して報告する
- ゲーム領域の検出: 正解の四角形との4隅のずれが、元画像のゲーム領域の幅の1%以内(仮)。ゲーム領域を検出できない棄却画像は採点しない
- 処理時間: 前処理を含めて、検証セット全体で1枚あたり5秒以内(仮)。上限は全画像の95%が収まる時間で判定する。計測は決めたCPU(未決事項)で行い、別のCPUの結果は参考値として扱う
- 低解像度: 元画像でのゲーム領域の幅が基準値未満なら、警告を付けたうえで受理する(基準値は未決)
